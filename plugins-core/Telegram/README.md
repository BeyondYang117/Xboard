# Telegram 插件

XBoard Telegram Bot 提供按钮菜单、双向工单、账户概览、流量查询、订阅链接和自动提醒，保留原有命令与管理员通知。

## 用户功能

- `/start` 或 `/menu`：打开可点击的菜单。
- `/account`：查看绑定账号、套餐、状态、到期时间、已用/剩余流量、下次流量重置时间及余额。
- `/bind [订阅链接]`：绑定账号，支持查询参数和路径形式的订阅链接。
- `/traffic`：查看流量，超额使用时剩余流量显示为 0。
- `/getlatesturl`：获取订阅链接，关闭链接预览并原样保留链接中的特殊字符。
- `/reminders`：开启或关闭到期、流量提醒，与网站的 `remind_expire` / `remind_traffic` 开关同步。
- `/tickets`：查看自己的工单列表和消息历史，支持翻页、回复和关闭。
- `/newticket`：分步输入标题与内容，提交给客服。
- `/cancel`：取消当前工单输入，返回菜单。
- `/unbind`：显示解绑确认按钮；确认后清除当前 Telegram 的全部账号绑定。
- `/help`：查看命令帮助。

所有账号操作仅限私聊。一个 Telegram 账号只能绑定一个站内账号；发现旧版本留下的重复绑定时，会提示先解绑后重新绑定，避免展示错误账号信息。

## 网站绑定与解绑

新版用户门户的个人中心提供 Telegram 绑定入口。点击“绑定 Telegram”生成链接，再点击“打开 Telegram”，在私聊中核对账号并点击“确认绑定”。仅打开链接不会直接绑定；返回网站时自动刷新状态，也可点击“刷新绑定状态”。无需把长期有效的订阅链接发给机器人。

绑定链接使用随机凭证，5 分钟有效、仅能使用一次；缓存仅保存凭证哈希。重新生成会使旧链接失效，确认时重新检查账号状态、双方绑定关系及 Bot 配置，Bot Token 更换后旧链接也失效。链接属于临时凭证，请勿转发给他人。可在个人中心撤销未使用链接，过期后需重新生成。

已绑定用户可在个人中心确认解绑，即使 Bot 已关闭或无法访问 Telegram 也能操作。网站只解除当前登录账号的绑定，不会清除其他账号的历史重复绑定。解绑会撤销该账号未使用的绑定链接。原 `/bind [订阅链接]` 继续兼容，绑定成功也会撤销未使用链接。

| 登录后 API | 方法 | 说明 |
| --- | --- | --- |
| `/api/v1/user/telegram/createBindingLink` | POST | 返回 `url`、Unix 秒时间戳 `expires_at`；每分钟最多 10 次，响应禁止缓存 |
| `/api/v1/user/telegram/unbind` | POST | 解除当前账号绑定并撤销未使用链接；重复请求安全 |

链接签发及确认要求站点 Bot 和 Telegram 插件同时开启。无需新增数据库字段；多实例需要共享缓存。网站入口需重新构建并安装用户门户主题。

## 双向工单

点击“联系客服”或发送 `/newticket` 后，先发送标题，再发送问题详情。标题最多 120 字，内容最多 3500 字，默认优先级为“中”。每个输入步骤 15 分钟内有效，发送 `/cancel`、打开菜单或使用其他命令即可结束输入。输入只暂存在缓存中，内容提交后才创建工单；解绑或切换站内账号后，旧草稿不能用于新账号。

`/tickets` 每页显示 5 个工单，消息历史每页显示最近的 2 条记录，可继续查看更早的记录。长消息在 Telegram 中显示摘要，完整内容可登录网站查看。工单页面支持“回复工单”和“关闭工单”，关闭需要确认，关闭后保留历史但不能继续回复。

客服从网站或 Telegram 回复后，已绑定的用户会收到通知，可以直接回复该通知继续沟通。用户仅能访问自己的工单；TG 和网站共用“一个用户只能有一个未关闭工单”及 `ticket_must_wait_reply` 规则。未绑定或停用的账号不能使用 TG 工单。

| 配置项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `enable_user_tickets` | boolean | true | 开启 TG 用户工单 |
| `enable_user_ticket_notify` | boolean | true | 将客服回复推送给已绑定用户；需同时开启用户工单 |

用户回复通知在数据库事务提交后加入 `send_telegram` 队列，发送时重新校验插件配置、工单归属、用户状态和绑定关系。只有发送成功才记录去重标记（保留 7 天）；通知失败按队列策略重试。Webhook 对同一 `update_id` 在 24 小时内去重，防止 Telegram 重复投递造成重复输入或回复。多实例应共享缓存，清理缓存会重置这些记录。

## 自动提醒

启用插件且开启站点 Telegram Bot 后，每 15 分钟检查一次，由 `send_telegram` 队列发送。发送前重新读取账号、绑定关系、用户开关和插件配置；账号解绑、停用、续费、流量重置或插件关闭后，失效的排队提醒会被跳过。

| 配置项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `enable_expire_reminder` | boolean | true | 开启套餐到期提醒 |
| `expire_reminder_days` | string | `7,3,1` | 到期前提醒天数，逗号分隔，范围 1–365 |
| `enable_traffic_reminder` | boolean | true | 开启流量不足提醒 |
| `traffic_reminder_percent` | string | `80` | 已用流量达到该百分比时提醒，范围 1–100 |

到期阶段按剩余时间向上取整，例如还剩 2 天 12 小时属于“3 天内到期”。每个账号、绑定关系、到期时间及提醒阶段只通知一次；流量提醒在同一流量周期每 24 小时最多一次。只有发送成功才写入去重记录，失败可由队列重试。缓存清理会重置去重记录。

提醒需要正常运行 Laravel 调度器和 `send_telegram` 队列消费者。多实例部署应共享缓存，以协调绑定锁、调度锁和提醒去重。

## 管理员功能

- 工单创建及用户回复：通知已绑定的管理员和客服。
- 支付成功：通知已绑定的管理员和客服。
- 管理员或客服可在私聊中直接回复机器人发出的工单提醒；普通账号、停用账号、群聊和已关闭工单无法使用此入口。
- 保留原有按账号有效性审核入群申请的功能。

| 配置项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `enable_ticket_notify` | boolean | true | 管理员工单通知 |
| `enable_payment_notify` | boolean | true | 管理员收款通知 |
| `auto_reply` | boolean | true | 未知私聊消息自动回复 |
| `help_text` | text | 菜单/帮助提示 | 未知消息回复文本 |

欢迎页继续支持 `start_welcome_title`、`start_bot_description`、`start_bind_guide`、`start_unbind_guide`、`start_bind_commands` 和 `start_footer`；文本中的字面量 `\n` 会转换成换行。

## 更新后使用

1. 在后台确认 Telegram Bot 和 Telegram 插件已启用，检查新增的提醒配置。
2. 在后台重新设置 Telegram Webhook，更新 Telegram 命令列表并明确接收按钮回调。
3. 重启常驻 Web / 队列进程以载入新代码。
4. 私聊机器人发送 `/start`，查看按钮菜单。

不需要新增数据库字段。消息以 POST JSON 发送；HTTP 连接/请求超时为 5/10 秒，队列任务超时为 30 秒。队列处理暂时性错误和 Telegram 的 `retry_after`，400/401/403 等永久错误直接失败。消息正文、订阅链接和含 Bot Token 的请求 URL 不会写入 Telegram 请求错误日志。
