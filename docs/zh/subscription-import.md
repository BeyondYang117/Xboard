# 机场分组、订阅导入与中转计费

更新后先在运行 Xboard 的环境执行 `php artisan migrate --force`，重启应用和定时任务进程。

## 机场分组管理

管理后台节点页面右下角点击「机场分组 / 订阅导入」。每个完整订阅链接对应一个机场分组；机场名称与用户套餐的权限组分别管理。

1. 粘贴机场 HTTP / HTTPS 订阅链接，获取并预览，默认全选可解析节点。
2. 设置机场名称、权限组、分发模式、计费倍率。新机场默认中转计费；配置过统一中转入口后自动使用同一域名和端口，无需逐个机场部署。
3. 可设置机场最大在线数、限制口径、周期流量总额度与到期时间。0 表示不限。
4. 点击「导入所选节点」，关闭窗口刷新节点列表。

已导入的机场可直接编辑设置、整组启停、显示或隐藏全部节点、重置机场周期流量、删除机场及其所有节点。删除前会确认，其他机场和自建节点不受影响；用户、套餐和历史流量统计保留。周期重置只重置机场的实际用量，不退还用户已扣流量，也不删除历史统计。后台同时展示在线用户数、来源 IP 数、TCP 连接数与机场总用量。

保存机场的权限组或倍率会批量应用到全部成员节点；之后可在节点列表单独调整倍率（包括时段倍率）。普通重新导入只更新选中的节点及其权限组/显示设置；保留现有倍率，除非明确提交 `rate`。机场层的权限组也是共同访问边界，节点权限组必须与机场权限组同时允许该用户。

历史导入记录在迁移时按来源自动归组，保留原有直连模式。切换中转前先部署中转服务；以前导出的上游凭据需在机场端更换才能失效。

## 为什么计费需要中转

直连模式向客户端发送机场原始凭据，平台无法获知每个用户的实际流量和在线状态，也不能使客户端已保存的凭据失效。直连模式的流量/在线数显示为「无法统计」，不允许配置有效的在线上限或机场流量限额。

中转模式向客户端发送平台 TLS HTTP CONNECT 入口和用户个人凭据，保留原节点名称；客户端不会收到机场密码、上游地址和协议配置。客户端流量由中转服务经 sing-box 发往原机场节点。

中转建立连接时检查用户封禁、到期、剩余流量、机场启停/到期/总额度、机场和节点权限组、节点显示及自身额度，以及用户设备限制。机场离线时不向订阅分发中转节点；已保存配置的接入仍要经过上述实时检查。

- 用户上传/下载按节点当前倍率扣除套餐流量，写入现有用户日统计。
- 节点与机场按实际转发字节累计上传/下载，节点写入现有日统计；机场总额度由所有节点共享。
- 每条连接使用累计字节计费，数据库事务同时更新流量和会话进度。重复结算或重启后的重试不会重复扣费。
- 每 10 秒结算、刷新会话和检查权限。到期、停用、删除、额度用完、计费失败后断开连接。存在最多一个结算周期和网络缓冲的延迟/流量超额，不是逐字节硬配额。
- 结算前将累计值暂存于 `storage/subscription-gateway/{机场ID}`，失败时关闭连接并重试；重启重放暂存记录。进程或机器突然崩溃可能丢失上一次结算后尚未暂存的字节（最多约 10 秒），正常停止会结算。统一入口的记录位于 `storage/subscription-gateway/shared`；需持久保存整个 `storage/subscription-gateway` 并确保可写。
- 会话租约为 60 秒，失效租约不能通过后续上报复活；定时清理会刷新受影响用户的在线设备数，30 天后清理旧会话。不会在清理时删除用户和节点日统计。

## 在线上限口径

机场的所有节点与中转实例共享数据库名额。接入在机场记录行锁内完成，避免并发分配超额；关闭连接释放名额，异常退出的名额在租约到期后释放。

| 口径 | 含义 |
| --- | --- |
| 来源 IP（默认） | 同一客户端 IP 跨节点、跨用户只占一个机场名额；同一 NAT 下多台设备不能区分 |
| 在线用户 | 同一平台用户跨 IP、跨节点只占一个名额 |
| 同时连接数 | 每条 TCP 连接占一个名额，包括同一用户/IP 的多个连接 |

用户个人设备限制仍按来源 IP 去重，并与现有自建节点的设备记录合并。平台统计的是客户端到中转入口的来源 IP；机场提供商看到的是中转机出口 IP。**提供商的设备数、IP 数、连接数口径不一定相同**，本功能无法直接获知其内部计数。一个客户端可能建立很多 TCP 连接，连接上限需要留出余量；同一机场凭据在平台外的使用也不计入平台上限。可通过较保守的连接上限与单一出口部署控制消耗，但不能保证提供商绝不触发限制。

降低上限后，下一次结算关闭超出新上限的会话，其他会话继续使用。启停、权限变更、删除和机场总额度耗尽也在下一次检查生效。

## 部署中转服务

中转需要 Linux PHP CLI（pcntl、posix、PDO、OpenSSL）、可执行 sing-box（项目镜像已包含，路径由 `NODE_PROBE_BINARY` 设置）和有效 TLS 证书。中转运行环境需可访问平台的同一数据库、共享缓存与机场节点，且使用同一个 `APP_KEY`。中转监听端口必须在 Docker/主机防火墙放行，域名指向中转机器。建议使用 Redis 共享缓存，不要使用进程内 array 缓存。

推荐使用**一个统一 TLS 入口**，不需要机场 ID，可以在尚未导入任何机场时启动。服务每 10 秒自动发现新机场，并按用户凭据中的节点编号选择所属机场。各机场仍独立计费、统计在线和执行总额度/在线上限。新增、删除或修改某个机场只更新对应的内部 sing-box 进程，不中断其他机场。

在所有应用容器共用的 `.env` 中一次性配置：

```dotenv
SUBSCRIPTION_GATEWAY_HOST=relay.example.com
SUBSCRIPTION_GATEWAY_PORT=2443
SUBSCRIPTION_GATEWAY_CERT=/certs/fullchain.pem
SUBSCRIPTION_GATEWAY_KEY=/certs/privkey.pem
```

域名解析到中转服务器，证书必须匹配域名。Cloudflare 使用仅 DNS，普通橙云代理不支持这个 TCP 入口。证书由中转直接使用，不经过面板的 HTTP 反向代理。可以复用面板域名及其有效证书，另用 2443 端口。

统一入口生效后，后台显示一次性入口配置；新机场导入自动填写它。已有中转机场订阅也自动使用统一地址，无需重新导入。已有直连机场仍保持直连，需要在后台切换为中转计费。修改 `.env` 后重建 Web、队列、WebSocket 和中转容器（若缓存过 Laravel 配置，先清理配置缓存），客户端更新订阅。

直接启动的命令不再带机场 ID：

```sh
php artisan subscription:gateway
```

该命令前台运行，使用 Supervisor、systemd 或容器保持运行。只有需要保留旧的独立入口时才使用 `subscription:gateway 1`；未配置全局入口时读取该机场自己的域名和端口，不要让多个监听进程占用同一端口。

### Docker：现有应用采用 host 网络

适用于 MySQL 和 Redis 均位于宿主机（例如 `127.0.0.1`）的部署。保持现有 Compose，另外将仓库的 `compose.gateway.host.sample.yaml` 保存为部署目录的 `compose.gateway.yaml`。它只新增一个中转容器，不启动 Web、队列或另一套 Redis，也不自动执行迁移。

1. 在现有 `.env` 添加上面的统一入口配置。
2. 创建 `certs/relay` 与 `storage/subscription-gateway` 目录；将完整证书链和私钥作为实际文件放在 `certs/relay/fullchain.pem`、`certs/relay/privkey.pem`。若源文件是 Let's Encrypt 符号链接，使用 `cp -L` 复制文件内容，或自行将完整证书目录挂载到相同绝对路径。私钥保持只允许管理员读取。不要将证书放到 `public` 目录。
3. 在云安全组与主机防火墙放行 TCP 2443（如使用其他端口则对应调整），确认未被其他进程占用。
4. 拉取新镜像，并重建现有应用容器，使它们读取新的统一配置。以下例子是 `web/horizon/ws-server` 的拆分部署：

```sh
docker-compose pull web horizon ws-server
docker-compose up -d --force-recreate web horizon ws-server
docker-compose -f compose.gateway.yaml up -d
docker-compose -f compose.gateway.yaml logs --tail=100 airport-gateway
```

中转日志会出现 `subscription-shared`。没有机场时可以正常等待；之后导入的中转机场在下次发现后显示“中转在线”，不需要重启或新增容器。删除全部机场后服务仍继续运行，等待下一次导入。不要使用 `--remove-orphans` 删除其他 Compose 文件管理的容器。

中转容器使用与主应用相同的 `.env`，因此 `APP_KEY`、数据库、Redis 缓存及前缀保持一致。模板按 MySQL 设计；SQLite 还需挂载与主应用相同的实际数据库文件。桥接网络部署应加入主应用的网络并挂载相同数据，不能直接使用宿主机 `127.0.0.1` 示例。

证书续期后同步更新挂载目录中的文件并重启中转容器；证书目录采用整体挂载，文件替换可见。更改统一域名或端口时，也需重建应用与中转，并让客户端更新订阅。一个机场的节点协议无法被内核接受时，仅该机场离线，修正后自动重试。

中转当前只支持 **TCP CONNECT**，不支持 UDP/QUIC、UDP 游戏和 HTTP 明文正向代理。客户端应支持 TLS HTTP 代理，使用 Clash Meta、sing-box 等兼容配置；上游机场仍可使用 Hysteria2 等协议转发 TCP。中转不提供用户套餐速率整形。每个机场任一启用节点的协议或参数不被内核接受，会使该机场中转启动失败，请先用节点测试确认配置。TLS 在入口服务直接终止，不应放在普通 HTTP 反向代理后；若使用四层代理，应保留来源地址，否则来源 IP 统计会合并。

## 解析、更新与凭据存储

支持明文节点链接、Base64 / URL-safe Base64 订阅和包含 `proxies` 的 Clash YAML / JSON。支持 Shadowsocks（含 SS2022）、VMess AEAD、VLESS、Trojan、Hysteria2、AnyTLS，以及常见 TCP、WebSocket、gRPC、HTTP/2、VLESS / Trojan Reality 配置。不支持的旧版 VMess、自定义 ALPN、TUIC、SSR、XHTTP、端口跳跃等会报告跳过原因；不导入 Clash 规则或代理组。

预览有效期 10 分钟，绑定创建它的管理员。每次最多导入 1000 个节点，下载上限 2 MB。订阅源与重定向使用公网地址；中转内核解析的上游节点也要求公网地址。

再次导入同一完整链接，以协议、名称、地址、端口识别已有节点并更新认证/连接参数，保留标签、排序、人工分类、流量记录。未选节点和订阅源消失的节点不自动删除；名称/地址/端口/完整链接变化会新增记录，请在管理页处理旧节点。目前使用手动导入，不自动保存链接或定时更新。

平台只持久保存订阅来源哈希，不保存完整 URL。节点密码及预览缓存加密，需保留原 `APP_KEY`；管理员列表和预览响应不返回密码。订阅链接与预览令牌不写入管理审计日志。中转内核配置包含上游凭据，使用权限为 0600 的临时文件，进程停止时清除，禁止将该目录或内核日志对外公开。

## 管理 API

接口前缀 `/api/v2/{后台安全路径}/server/manage`，要求管理员认证。

- `POST /previewSubscription`：`subscription_url`；返回 `preview_token`、安全节点摘要、`skipped`，以及已有机场的设置 `subscription`（若存在）。
- `POST /importSubscription`：`preview_token`、`node_keys`、`group_ids`、`show`，可带下述机场设置；返回 `created`、`updated`、`subscription_id`。导入使用预览内容，不重新下载。新机场默认 `delivery_mode=relay`。
- `GET /subscriptionGateway`：返回统一入口 `host`、`port` 和服务 `online`，仅管理员可用。
- `GET /subscriptions`：机场设置、节点数、三种在线计数、实际用量、可用状态、网关心跳。不返回来源哈希、订阅链接或上游凭据。
- `POST /saveSubscription`：`id` 和要更新的字段；`group_ids`、`show`、`rate` 同时应用成员节点。`reset_usage=true` 重置机场周期用量。
- `POST /deleteSubscription`：`id`，事务删除机场与成员节点，返回 `deleted` 节点数，保留日统计和会话最终结算记录。

机场设置：`name`、`enabled`、`delivery_mode`（`relay/direct`）、`rate`、`max_online`（0 不限）、`online_limit_mode`（`ip/user/connection`）、`gateway_host`（纯域名/IP）、`gateway_port`、`transfer_enable`（字节，0 不限）、`expired_at`（Unix 秒或 null）。`group_ids` 使用现有权限组 ID。配置统一入口后，中转机场的 `gateway_host` / `gateway_port` 自动使用全局配置。多个机场允许共用同一入口，按节点编号路由。机场最大在线上限仅用于真实接入检查，不以订阅下载次数或流量上报条目数量代替在线人数。
